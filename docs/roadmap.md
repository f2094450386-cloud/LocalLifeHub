# 改造路线图

## A. Redis + Lua 秒杀防超卖与一人一单

梳理现有 `seckill.lua`、库存 Key、订单 Set、Redis Stream 写入逻辑，补充初始化脚本和接口测试用例，明确防超卖与一人一单的验证方式。

## B. RocketMQ 异步下单与消费幂等

在 Redis Stream 基线稳定后，引入 RocketMQ 做订单消息异步解耦。重点设计 Topic、Tag、消息体、消费幂等表或幂等 Key、重试和补偿逻辑。

## C. 未支付订单超时关闭

增加订单状态流转，设计待支付、已支付、已取消等状态。通过延迟消息或定时补偿关闭超时订单，并回补库存。

## D. 商户缓存治理：穿透、击穿、雪崩、缓存一致性

系统化整理商户查询缓存策略，包括空值缓存防穿透、互斥锁/逻辑过期防击穿、TTL 随机化防雪崩、更新商户时删除缓存或延迟双删。

## E. AOP + Redis 滑动窗口限流

设计自定义限流注解，使用 AOP 拦截接口请求，通过 Redis ZSet 或 Lua 实现滑动窗口限流，先覆盖登录验证码、秒杀下单等高风险接口。

## F. LangChain4j + 阿里云百炼 AI 客服

接入 LangChain4j 和阿里云百炼 OpenAI-compatible API，使用环境变量配置 API Key。先实现基于商户、优惠券、订单规则的问答，不硬编码密钥。

## G. 接口测试文档和简历版本整理

沉淀 Postman 或 curl 用例、启动依赖、压测记录和功能截图。简历中只写已经在代码、接口、SQL、文档中落实的能力。
